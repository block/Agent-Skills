# Video type and script

Choose the evaluation function before choosing visual style. A technically polished tutorial can fail if it is hard to reproduce; a clear tutorial can fail as a promo if it creates no desire or memorable value.

## Route by type

| Type | Primary outcome | Default grammar | Protect at all costs |
| --- | --- | --- | --- |
| Tutorial | Viewer successfully reproduces a result | Linear steps, real operation, stable framing, restrained motion, readable holds, recovery | Completeness, clarity, state continuity |
| Promo | Viewer understands value and takes action | Strong opening, emotional arc, concept + proof, rhythm, brand memory, CTA | Truth, interest, evidence, brand distinction |
| Hybrid | Desire first, then compact proof | Promo hook + selective tutorial proof + brand close | One explicit dominant objective |

Do not use a hybrid label to avoid prioritization. Record `conversion_first` or `learning_success_first`.

## Build a promo script

Before drafting the timed script, offer 2–3 treatments that differ in more than wording. Each treatment must include:

- opening hook;
- core concept or metaphor;
- claim/proof structure;
- emotional peak;
- CTA;
- production implications.

After the user chooses, create timed units. Give each unit:

- `unit_id`;
- time range or target duration;
- narrative job;
- visible copy;
- voiceover;
- claim IDs;
- proof;
- emotion;
- action;
- asset implications;
- effect needs.

Keep one primary visual focus per unit. Do not compensate for an unclear claim with more effects.

## Build a tutorial script

Structure from outcome backward:

1. Show the final result or state the promise.
2. Establish the clean starting state.
3. List only necessary actions.
4. Define the visible success state for every action.
5. Include waiting, errors, or recovery only when viewers need them.
6. Close by confirming the reproducible result.

Write capture commands separately from narration. Do not make the operator improvise around live latency. Use deterministic fixtures, a clean account, and segmented recording when online responses are unstable.

## Build a hybrid script

Use three parts:

1. `desire`: why the result matters;
2. `proof`: the shortest truthful path showing it works;
3. `action`: what the viewer should do next.

Avoid presenting a full tutorial inside a short promo. Link or branch to a longer tutorial when completeness would destroy promo rhythm.

## Maintain claims and proof

Map every external claim:

`claim → source truth → source asset → script unit → final timestamp`

Classify proof as:

- `real_ui`;
- `real_output`;
- `verified_data`;
- `approved_testimonial`;
- `physical_product`;
- `concept_only`.

If no evidence exists, remove the claim, label it as a concept/future direction, or request a real capture. Never use simulated UI or AIGC as silent factual proof.

## Lock the script

Before approving P3:

- confirm the selected treatment;
- confirm visible copy and narration direction;
- check total target duration against the delivery envelope;
- identify every claim and CTA;
- derive asset implications;
- derive effect needs;
- mark each effect need `must_have` or `optional`;
- mark whether an effect reference is `required`, `optional`, or `none`.

When the script changes, invalidate downstream effect references, AE candidates, asset requests, timing, audio cues, and authorization only where their referenced unit changed.
